# 频道批量下载：开发计划与学习记录

## 工作流程

Issue 记录问题与验收条件 → 分支隔离修改 → commit 保存一个可说明的改动 →
自动测试检查行为 → Pull Request 展示代码和证据 → review 评审 → merge 合并 → release 发布。

Issue 不是代码；PR 不是已发布版本；测试通过不等于真实网络下载已通过。

## 第一版需求

输入频道主页，选择 Videos 或 Shorts，或选择频道的一个播放列表；先扫描、再勾选视频，
选择清晰度和字幕语言，下载到本地。保留单视频链接支持。

扫描不得下载媒体。列表去重使用视频 ID。单项失败不终止整批。取消在安全检查点生效，
保留部分下载供下次继续。默认不主动读取浏览器登录信息。

字幕使用现有人工字幕，按需启用自动字幕；保存 SRT。无字幕继续保存视频并明确显示。
已下载的视频再次请求字幕时必须允许补字幕。字幕不包含语音识别或翻译。

## 三个任务

1. 总体需求和验收跟踪。
2. 频道路由、扫描、队列、字幕及中文界面。
3. 自动测试、依赖清单、可移植 Windows 打包与文档。

## 架构决策

- 继续使用 Python 和现有 CustomTkinter，复用 yt-dlp、ffmpeg、Deno 查找函数。
- 下载服务与界面分离：服务可以独立测试；后台线程通过队列通知主线程。
- 首版顺序处理视频，降低限流和状态复杂度。批量不等于多个视频同时传输。
- 历史记录保存在选定下载目录，不发送到云端。

## 验收门槛

- 自动测试：网址边界、列表去重、失败继续、取消、历史与字幕补下载。
- 实网：Huberman 栏目读取、一个视频及其字幕下载；记录失败原因而不伪报通过。
- 界面：扫描、勾选、开始、取消、重试与错误显示。
- 交付：Windows 打包和安装启动分别记录，未测试不写已通过。

## 延后范围

Podcasts 入口、热门排序、社区帖子、付费/私密内容、定时订阅、翻译、语音识别。
